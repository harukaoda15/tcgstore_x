## 初期運用方針（2026-03）

- 初期公開は `上位10件` の固定テンプレ投稿で開始する
- 裏側では `上位50件` を毎日取得してKVに蓄積し、将来の週次/月次比較に備える
- 投稿文はAIを使わず、取得日時と引用元URLを含む定型文のみで運用する
- 画像添付は著作権・転載可否の確認後に有効化し、初期はテキスト投稿を優先する
- 投稿頻度は `1日1回` を基本とし、まずは継続性とデータ欠損率を確認する

## 概要

pokeca-chart.com からポケカ相場を取得し、毎日 18:00 JST に日次スナップショットを保存、21:00 JST にその保存済みデータから X へ自動投稿する機能。

## 仕様

| 項目 | 内容 |
|------|------|
| **取得** | 毎日 18:00 JST（cron: `0 9 * * *`） |
| **投稿** | 毎日 21:00 JST（cron: `0 12 * * *`） |
| **データ元** | pokeca-chart.com |
| **取得件数** | `rank_rise_7` / `rank_fall_7` / `rank_vol` を各上位50件で日次保存 |
| **KV キー** | `pokeca_summary:{YYYY-MM-DD}:{rankTarget}` |
| **R2 キー** | `pokeca-summary/{YYYY-MM-DD}/...`（画像アーカイブ有効時） |

### データ取得フロー

1. **18:00 JST** → `pokeca-chart` のAPI/同等データソースを1回取得し、`rank_rise_7` / `rank_fall_7` / `rank_vol` を生成
2. **整形** → カード名、価格、カードURL、画像URLを日次スナップショット化
3. **画像保存（任意）** → R2 へ画像を保存し、KVには `imageR2Key` を記録
4. **KV保存** → `pokeca_summary:{YYYY-MM-DD}:{rankTarget}` に保存
5. **21:00 JST** → 保存済みスナップショットを使って投稿

### 投稿テーマ

- `rank` パラメータ指定時は手動テーマを優先
- `rank` 未指定時は曜日テーマを自動適用
- 曜日テーマ（JST）
  - 日: `rank_vol`（取引件数）
  - 月・木: `rank_rise_7`（高騰）
  - 火・金: `rank_vol`（取引件数）
  - 水・土: `rank_fall_7`（下落）
- 投稿文には `観測メモ:` の一言要約を自動挿入（そのまま転載に見えない運用）

### 投稿形式

- 見出し: `【M/D(曜)テーマ名】`
- 本文: 上位10件（文字数上限に収まる範囲で表示）
- 画像: 最大 3 枚（pokeca-chart の og:image）
- ハッシュタグ: `#ポケカ`

### 現在の投稿件数方針

- 公開投稿: フルネーム + 価格を優先し、`TOP10 -> TOP8 -> TOP5` の順で自動縮小
- 現在の実運用: `TOP5`
- 画像保存: `POKECA_IMAGE_ARCHIVE` (R2 binding) がある場合、画像URLだけでなく画像本体も保存

### 手動実行

- プレビュー: `/?mode=pokeca_summary_preview`
- 実投稿: `/?mode=pokeca_summary&commit=1`
- デバッグ: `/?mode=pokeca_summary_debug`
- 備考: 自動投稿時は 21:00 JST に当日 18:00 JST 保存分を優先利用する

## 技術メモ

- 自動投稿は保存済みスナップショット優先。18:00 JST の取得が失敗していた場合のみ、21:00 JST 投稿時に再取得でフォールバックする
- 価格・ランキング取得は `pokeca-chart` のトップページ描画と同一系統データを使用する
- 画像 alt はカード名を明示して設定する
